# GitFlow Pro 使用文档

> 版本：v1.0.0 ｜ 平台：Windows 10 / 11（64 位）｜ 作者：mosunand
>
> GitFlow Pro 是一款以 **GitHub / Gitee** 为核心的桌面 Git 客户端，用 C++ / Qt 6 开发。
> 把日常 Git 操作、代码编辑、仓库管理、代码运行和 Release 发布整合进一个窗口，
> 让你不必背命令行也能完成绝大部分版本控制工作。

## 1. 环境要求

| 依赖 | 是否必须 | 说明 |
|------|----------|------|
| Windows 10 / 11（64 位） | ✅ 必须 | Qt 6.8.3 运行库已随包附带，无需另装 |
| **Git**（已加入 PATH） | ✅ 必须 | 所有仓库操作、内嵌终端都依赖它。没装请先到 <https://git-scm.com> 安装 |
| python / node / g++ / javac | ⭕ 可选 | **只有使用"运行代码"功能时**才需要对应语言的解释器/编译器，且需加入 PATH |
| 浏览器 | ⭕ 可选 | 运行 `.html` 文件时用系统默认浏览器打开 |

**检查 Git 是否可用**：按 `Win + R` 输入 `cmd` 回车，再输入 `git --version`。
能看到版本号（如 `git version 2.45.0`）即说明已加入 PATH。

## 2. 安装与启动

### 方式 A：安装包（推荐）

1. 双击 `GitFlowPro-Setup-v1.0.0.exe`
2. 按中文向导点击"下一步"，默认安装到 **用户目录**（`%LOCALAPPDATA%\GitFlowPro`），**不需要管理员权限**
3. 可勾选"创建桌面快捷方式"
4. 安装完成后可勾选"立即运行"

卸载：Windows"设置 → 应用"里找到 GitFlow Pro，或开始菜单里的卸载项。卸载会连同运行产生的 `data/` 数据一起清理。

### 方式 B：便携 ZIP（免安装）

1. 解压 `GitFlowPro-v1.0.0-Windows.zip` 到任意目录（如 `D:\Tools\GitFlowPro`）
2. 双击其中的 `GitFlowPro.exe`

> 软件是绿色便携的：所有数据（账户、设置）都保存在 **exe 同目录** 的 `data/` 文件夹里，
> 换电脑时把整个文件夹拷走，数据也跟着走。**不要把 `data/` 分享给别人。**

## 3. 首次配置：连接 GitHub / Gitee 账户

推送、拉取私有仓库、Fork、发布 Release 等远程操作都需要一个账户 Token：

1. 打开菜单 **设置 → 连接用户**（或左侧"连接"菜单）
2. 选择平台（GitHub 或 Gitee），输入用户名，粘贴 Token
3. （可选）填写 **Token 有效期（天）**：到期前标题栏会倒计时提醒，≤7 天红色加粗
4. 软件会验证 Token 并**加密保存**（Windows CNG AES-256-GCM，密钥随机生成，只存本地）

**Token 怎么获取：**

- **GitHub**：网页右上角头像 → Settings → Developer settings → Personal access tokens →
  Generate new token。勾选 **repo** 权限（私有仓库必需）；要发 Release 勾选内容写权限。
- **Gitee**：网页右上角头像 → 设置 → 私人令牌 → 生成新令牌。勾选 **projects** 等权限。

> ⚠️ Token 相当于密码，只粘贴给本软件，不要发给别人。
> 若仓库面板提示 "Token 无效或已过期 / 尚未连接账户"，到这里重新添加即可。

## 4. 打开 / 初始化仓库

- **打开已有仓库**：工具栏 **打开项目**（或 `Ctrl+O`），选择一个 Git 仓库目录
- **新建仓库**：菜单 **文件 → 初始化仓库**，选择一个空文件夹，软件会执行 `git init`
- **直接拖拽**：把文件夹从资源管理器拖到窗口上即可打开
- 上次打开的仓库会在下次启动时自动恢复

## 6. 文件树与右键菜单

左侧文件树只加载第一层，**展开目录时才懒加载子层**，大仓库也不卡。
展开状态会被记住，刷新后自动恢复。

**右键某个文件**，可以：

| 菜单项 | 作用 |
|--------|------|
| 打开编辑 | 在右侧编辑器打开（文本直接编辑，图片进入预览） |
| **运行** | 运行该代码文件（见第 8 节） |
| 查看差异 | 显示该文件未提交的改动（Diff 页签） |
| 查看Blame | 逐行显示最后修改者 |
| 放弃更改 | 恢复到上次提交的状态（**不可逆**，会弹确认） |
| 删除文件 | 删除该文件（会弹确认） |

**右键空白/目录**：新建文件、添加文件（从别处复制进来）。

## 7. 代码编辑器

- 语法高亮：Python / C/C++ / Java / JS/TS / HTML / CSS / Rust / Go 等
- 行号、当前行高亮、缩进参考线
- `Ctrl+F` 打开查找栏（Enter 下一个、Shift+Enter 上一个、Esc 关闭），输入时实时显示"第几个/共几个"
- `Ctrl+S` 保存
- `Ctrl+滚轮` 或 `Ctrl+=` / `Ctrl+-` / `Ctrl+0` 调整字号（10–16pt）
- 打开图片（png/jpg/gif/webp 等）进入预览模式，Ctrl+滚轮缩放，双击复位

> 双击文件树里的文件即打开编辑。修改后不会自动保存，保存方式：
> `Ctrl+S`，或运行代码时在"未保存提示"里选择"保存并运行"。

## 8. 运行代码（重点）

写完代码不用切出去，**直接在软件里跑**：

**三种方式任选：**

1. 工具栏 **▶ 运行** 按钮
2. 快捷键 `Ctrl+R`
3. 编辑器内**右键 → 运行**，或文件树里右键文件 → 运行

**支持的文件类型与所需环境：**

| 文件类型 | 使用的工具 | PATH 里需要有 |
|----------|-----------|---------------|
| `.py` | python 直接解释执行 | `python` |
| `.js` | node 执行 | `node` |
| `.ts` | ts-node 执行 | `ts-node` |
| `.c` `.cpp` `.cxx` `.h` | g++ 编译成同名 `.exe` 后自动运行 | `g++`（MinGW 等） |
| `.java` | javac 编译后用 java 运行 | `jdk`（javac + java） |
| `.html` `.htm` | 用默认浏览器打开 | 无 |

**运行流程：**

1. 软件自动在系统环境变量 `PATH` 里查找对应解释器/编译器
2. **找不到会弹窗提示**："未找到 xxx，请先在系统环境变量 PATH 中配置好解释器/编译器"，此时不会执行任何东西
3. 找到后自动打开内嵌终端、**先清屏**（和之前运行的输出分开，不会混在一起），然后执行
4. 终端工作目录自动切到**文件所在目录**，输出实时显示，结束显示退出码
5. C/C++/Java 编译产物（`.exe` / `.class`）生成在源文件同目录

**未保存提醒：**

如果编辑器里的代码改了但**还没保存**就点运行，会弹出提示：

> "当前文件有未保存的修改，可能运行的是旧代码。要先保存再运行吗？"

三个按钮：**保存并运行**（先落盘再跑，推荐）／ **仍然运行**（跑磁盘上的旧代码）／ 取消。

**配置 PATH 的方法（以 Python 为例）：**

1. 安装 Python 时勾选 "Add python.exe to PATH"；如果当时没勾：
2. `Win + S` 搜索"编辑系统环境变量" → 环境变量 → 在用户变量的 `Path` 里新增 Python 安装目录
3. **重启 GitFlow Pro**（PATH 只在进程启动时读取）

## 9. 提交 / 拉取 / 推送

### 提交

1. 左下角提交框输入提交信息（默认"更新了一些文件"）
2. 点 **提交**：自动暂存所有改动（含未跟踪文件）并提交
3. 点 **提交并推送**：提交完成后**自动接着推送**（不会推到旧版本）

### 推送

- 菜单 **Git → 推送**，会弹出**实时进度窗口**（传输百分比、逐行日志）
- **推送前自动扫描历史与工作区中超过 100MB 的文件**，发现会列出清单让你确认
  （GitHub 单文件上限 100MB，超限必被拒收）
- 失败时自动做网络诊断，常见原因是没开代理 / Token 权限不够

### 拉取

- 菜单 **Git → 拉取**，使用 `--ff-only` 快进合并，避免意外产生合并提交

> 已配置账户时推送/拉取通过 Token 认证（askpass 机制），不会再弹密码框。

## 10. 分支、标签、Stash 与回档

| 操作 | 入口 | 说明 |
|------|------|------|
| 切换分支 | 工具栏分支下拉框 | 选中即切换 |
| 新建分支 | 左侧 **+ 新分支** | 从当前 HEAD 创建 |
| Stash 暂存 | Git 菜单 → 暂存 | 把未提交修改收起来，可写备注 |
| Stash 恢复 | Git 菜单 → 恢复 | 取出最近一次暂存 |
| Stash 列表 | Git 菜单 → 暂存列表 | 查看所有暂存记录 |
| 打标签 | Git 菜单 → 创建标签 / 标签列表 | 默认轻量标签，可带说明 |
| 回档 | 历史列表右键提交 → 回退到此提交 | **硬重置**，会弹确认，未推送的提交和未提交修改都会丢 |

## 11. 提交历史与分支图

## 12. 仓库面板：搜索 / 克隆 / Fork / 新建仓库

入口：菜单 **连接 → 仓库搜索** 或 **Git → 搜索仓库**。

- 打开面板会自动列出**我的仓库**（需要已连接账户；未连接会提示先去添加）
- 搜索框支持三种输入：完整 URL（`https://github.com/owner/repo`）、`owner/repo`、用户名（列出其公开仓库）
- **克隆并打开**：双击列表项或点"克隆"按钮；克隆到本地存储目录并自动在主窗口打开
  （本人仓库放 `users/<用户名>/`，别人的放 `downloads/`，按平台分目录）
- **Fork**：选中他人仓库点 Fork，复制到你的账号下
- **新建仓库**：输入名字一键创建（自动带 README 初始化），创建完询问是否克隆到本地
- **浏览器打开**：跳转到该仓库网页

## 13. Release 发布（含预发布）

入口：仓库面板选中一个仓库 → **创建发布**。会弹出独立的大窗口：

1. **发布类型**：正式发布 / **预发布（Pre-release）**（GitHub、Gitee 均支持）
2. **版本标签**：如 `v1.0.0`；发布标题默认跟随标签，可改
3. **发布说明**：多行文本
4. **附件**：可添加多个文件，创建成功后逐个上传（进度实时显示）
5. 成功后自动打开浏览器跳转到发布页

**常见错误提示：**

- "xx 已经存在发布" → 换个标签号（如 `v1.0.1`）
- "找不到仓库" → Token 没有该仓库权限，或仓库不存在

## 14. 内嵌终端

- `Ctrl+`` （反引号）或 Git 菜单 → 终端面板 开关
- 底部输入命令，**回车执行**，真正跑在 bash（Git 自带）里，支持管道、重定向、`&&`
- **上下方向键**翻看命令历史
- 输出区格式：每条命令前空一行，回显为 **黄色加粗用户名 > 命令**
- 运行代码时会先自动清屏；手动输入命令不会清屏
- 支持 `cd` 切目录（影响后续命令的工作目录）、`clear`/`cls` 手动清屏

## 18. 数据存放位置与安全

所有数据都在 **exe 同目录的 `data/`** 下：

```
data/
├── settings.json          # 主题、语言、git 路径、上次打开的仓库
└── accounts/
    ├── current.txt        # 当前使用的账户标识
    └── github_用户名.json # 加密后的 Token（含 Token 有效期）
```

- Token 使用 **AES-256-GCM** 加密（Windows CNG），**每个账户独立随机密钥**
- 密钥和密文都只存在本地，**不上传任何第三方服务器**
- 备份 / 迁移：把整个 `data/` 文件夹拷走即可
- ⚠️ 不要把 `data/` 发给别人、传到公开仓库——虽然加密，但密钥就在旁边

## 19. 常见问题 FAQ

**Q1：双击 exe 没反应 / 闪退？**
确认解压完整（`platforms/qwindows.dll` 等文件夹必须和 exe 在一起），且系统为 64 位 Win10/11。杀毒软件误报时请加白名单。

**Q2：任务栏 / 快捷方式图标不对？**
Windows 图标缓存偶尔不刷新；重启资源管理器或重新安装一次即可。

**Q3：打开仓库没反应，提示不是仓库？**
该目录没有 `.git`。选择它会询问是否初始化为仓库。

**Q4：仓库面板提示 "Bad credentials" / Token 无效？**
① 未连接账户 → 到 设置 → 连接用户 添加；② Token 已过期/被撤销 → 网页端重新生成再添加；③ 连接的是 Gitee 却搜 GitHub（现已按平台自动路由，老版本请升级）。

**Q5：推送一直失败？**
① 检查能否在浏览器打开 github.com；② 开了代理软件的话软件会自动走代理，若仍失败重启代理软件再试；③ 检查 Token 是否有 repo 写权限；④ 看进度窗口里的具体报错。

**Q6：运行代码提示"未找到 xxx"？**
对应解释器没装或没加 PATH，见第 8 节"配置 PATH 的方法"。配置后**重启本软件**。

**Q7：C++ 编译报错找不到头文件？**
g++ 环境本身的问题（如 MinGW 未装全），先在系统命令行确认 `g++ 源文件.cpp -o test.exe` 能通过。

**Q8：切换语言/主题后个别文字没变？**
重新打开对应窗口即可；若仍存在请到开源仓库提 Issue。

**Q9：怎么彻底重置？**
关闭软件 → 删除 `data/` 文件夹 → 重新启动（所有账户和设置会清空）。

## 20. 已知不足与注意事项

- **不支持删除远程仓库、修改仓库公开/私有**等敏感操作，请到 GitHub / Gitee 网页端
- **单文件 >100MB 无法推送**（平台硬限制），请用 Git LFS 或移除该文件
- **可视化合并冲突**暂未实现，冲突请在终端用命令行处理
- 远程认证走 **HTTPS + Token**，暂不支持 SSH 密钥
- 回档（硬重置）不可逆，操作前想清楚
- 本软件按"现状"提供，**重要数据请自行备份**
